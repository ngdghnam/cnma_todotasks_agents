# Clean State Checklist

Use this list as a **dual gate**:

- **Cold-start gate.** Run it as the first thing in a new session, between
  step 1 (confirm repo root) and step 2 (read `ARCHITECTURE.md`) of the
  `AGENTS.md` startup workflow. If a box was claimed green but is actually
  red, repair or downgrade the claim before adding scope.
- **End-of-session gate.** Run it before closing any session and before
  flipping any `feature_list.json` entry to `passing`. If a box cannot be
  checked, document the exception in `PROGRESS.md` "Current Verified State"
  and in `session-handoff.json#active_blockers`. Never close green when a box
  is red.

The plan's closeout checklist (per `docs/04-project/harness/PLANS.md`) must reference this file.
The *close* stage in `docs/04-project/harness/engineering/implementation-workflow.md` requires
every box green.

## Operating Rules

- Run the checks in order; stop at the first red and fix it before continuing.
- Treat the table as the source of truth. Do not edit the wording without
  updating `AGENTS.md` "Startup Workflow" and "End Of Session",
  `docs/04-project/harness/PLANS.md` closeout checklist, and
  `docs/04-project/harness/engineering/implementation-workflow.md` close stage in the same
  change.
- If a check needs to be temporarily relaxed for a known reason, add a row to
  `docs/04-project/slices/02-exec-plans/tech-debt-tracker.md` and link it from `PROGRESS.md`. Do
  not silently lower the bar.
