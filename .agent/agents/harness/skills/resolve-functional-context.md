# Resolve functional context

Resolve the feature-implementation record, linked feature and user stories,
requirements, accepted decisions, active functional specification, and the
live BA state. Use project files as authority. Report a missing source,
contradiction, or undefined product behavior as a blocker; never repair it by
inventing a business rule.

For CAP/BTP work, distinguish a functional requirement from an implementation
choice. Functional context must state observable behavior, roles, validation,
error outcomes, integrations, data ownership, exclusions, and acceptance
criteria without binding the developer to a premature CDS or handler design.
